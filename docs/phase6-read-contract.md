# Phase 6 read contract

- “Today” in the overview is the calendar date in `Asia/Bangkok`. The overview card counts distinct employee IDs with at least one `recorded` charged day on that date; two half-day rows for one person still count as one person. Latest leave entries are counted as entries, show their full/half unit and status, and link to detail.
- Annual balances use `leave_entry_days.leave_date` within the selected calendar year and include only entries whose status is `recorded`. They sum charged days (including 0.5 days) by employee, leave type, and year. Cancelled entries remain searchable history but do not contribute. Quotas and remaining balances stay separate by leave type. Missing entitlement is labeled separately from a present entitlement with quota zero.
- History year filters apply to the leave-entry interval: `start_date <= Dec 31` and `end_date >= Jan 1`, inclusive. Explicit start/end dates intersect with the selected year; an empty intersection returns no rows. Date bounds are validated and an explicitly reversed range is shown as an error.
- History accepts employee, type, status, year, date range, and name/code search filters. Invalid or repeated URL values are surfaced in Thai. Search terms are applied to employee code, first name, and last name; multiple words must each match one of those fields.
- To keep PostgREST wildcard matching predictable, `*` is rejected in the search field; percent and underscore are escaped as literal characters.
- History pages contain 25 rows. The server applies filters before count and range, sorts by `created_at DESC, id DESC`, and clamps an out-of-range page to the last available page. Offset pagination is deterministic while the underlying result set is unchanged; new entries can shift later offsets between requests, so refreshing re-evaluates the current filters and count.
- Reading uses the authenticated staff Supabase client and existing RLS. Mutations continue through the Phase 5 RPCs; affected overview, history, detail, and employee pages are revalidated after successful writes. No Realtime subscription is used.
